# 文档体系说明

本目录把「**当前怎么算**」和「**为什么改成这样**」拆开维护，避免再把变更流水账堆进 `ALGORITHM_DOC.md`。

## 怎么读

| 路径 | 用途 | 何时更新 |
|------|------|----------|
| [`spec/`](spec/) | **活规格**：只写当前输入 / 公式 / 阈值 / API / 诚实口径 | 改引擎逻辑时同步改 |
| [`adr/`](adr/) | **决策记录**：每次重要算法/需求变更一张卡，写完不改旧卡 | 做决策时新增 |
| [`CHANGELOG.md`](CHANGELOG.md) | **人话变更摘要**：按日期按模块追加 | 每次可感知行为变化追加 |
| [`../ALGORITHM_DOC.md`](../ALGORITHM_DOC.md) | **架构总览 / 白皮书**：原理与系统结构；§9 起历史日志已冻结 | 仅改架构叙述，不再追加修正清单 |

## 改需求时的最小流程

1. 若涉及算法取舍：新建一张 `adr/NNNN-标题.md`（复制 [`adr/0000-template.md`](adr/0000-template.md)）
2. 更新对应 `spec/*.md` 为「现在的真相」
3. 在 `CHANGELOG.md` 顶追加一条（模块 + 行为变化 + 关联 ADR）
4. 再改代码；提交信息建议带 `[模块] … — ADR-NNNN`

## 三个月后自检

打开本目录，应能在约 10 分钟内回答：

- 每个引擎**现在**怎么算？→ `spec/`
- 最近几次**为什么**改？→ `adr/` + `CHANGELOG.md`
